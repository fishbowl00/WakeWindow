# Inknaut Labs — Brand Specification

Canonical publisher brand for every Inknaut Labs application. This document and the
assets alongside it in `branding/inknaut/` are the single source of truth. Copy this
whole directory into a new Inknaut Labs app's repository unchanged and implement
against it — never redraw, re-vectorize, or reinterpret the mark.

This pilot was built and verified in **NextUp** (Aug 2026), the first Inknaut Labs
app. RideCast, Abra, and future apps consume these same files without regenerating
anything.

## 1. Canonical master

`source/inknaut_master.png` is the approved, human-supplied reference artwork —
a finished lockup (symbol + wordmark) on a white background, at 1536×1362px. It is
kept unedited as the ground truth. Every other file in this kit is a **pixel-derived
transformation of this exact master** — cropped, alpha-extracted, and recolored, never
retraced or reconstructed by hand. An earlier pass on this project attempted to
reconstruct the mark as hand-authored vector/Bézier geometry from a text description;
that reconstruction was visually wrong (uneven stroke weight, incorrect tail and
circuit-terminal proportions) and was discarded in full once the actual master file
was supplied. **No vector or hand-drawn version of this mark exists or should be
created** — every production asset traces back to `source/inknaut_master.png` through
crop/alpha/recolor operations only.

## 2. Mark geometry (do not alter)

- Nautilus-style spiral (~2.3 visible turns), constant stroke weight, round caps and
  joins, extending into a tail that sweeps down and flattens horizontal.
- Three stepped circuit traces branch off the tail to three open-ring terminals,
  stacked vertically at the tail's end.
- Wordmark: **INKNAUT** (bold, wide letter-spacing) stacked above **LABS** (smaller,
  wider-spaced, always in the electric blue accent — the one place blue appears in
  text).
- The symbol's native aspect ratio is wide, not square (~1012×790 in the isolated
  crop). Do not stretch, squash, or force it into a square frame; if a platform API
  needs a square icon, pad the existing transparent symbol PNG onto a larger
  transparent square canvas, centered — a composite operation, not a resize/distort.
- Minimum practical size: the symbol becomes illegible below roughly 24dp/24px tall
  (the inner coil turns close up); the stacked lockup shouldn't render below ~120dp
  wide in-app.
- The symbol may be used alone. The wordmark is never used without the symbol in
  first-party publisher placements.

## 3. Colors

Measured directly from the master's own pixels (the modal/most-frequent exact RGB
value within each solid-fill region — spiral stroke for navy, "LABS" glyphs for
blue), not independently chosen. These are now final and canonical; reuse the exact
values below rather than re-picking a "close enough" navy/blue in a new app.

| Token | Hex | RGB | Use |
|---|---|---|---|
| Inknaut Navy | `#01172E` | `1, 23, 46` | mark + `INKNAUT` wordmark on light backgrounds; splash/background fill on dark |
| Inknaut Blue | `#0A6DE8` | `10, 109, 232` | circuit terminal rings, `LABS` text — the only accent color, used sparingly |
| Inknaut White | `#FFFFFF` | `255, 255, 255` | mark + wordmark on dark backgrounds; light splash/background fill |

Kotlin/Compose:
```kotlin
val InknautNavy = Color(0xFF01172E)
val InknautBlue = Color(0xFF0A6DE8)
val InknautWhite = Color(0xFFFFFFFF)
```
Android XML: `#FF01172E`, `#FF0A6DE8`, `#FFFFFFFF`.

These are **publisher** colors, not product colors. Do not pull Inknaut Navy/Blue into
an app's own UI palette, category colors, or component theming just because "it's the
brand" — each Inknaut Labs app keeps its own icon, product palette, and personality.
NextUp's own purple/pink Material palette is untouched by this branding pass.

## 4. Light and dark treatments

**Light**: white/transparent background; mark and `INKNAUT` wordmark in Inknaut Navy;
terminal rings and `LABS` in Inknaut Blue. File: `png/inknaut_lockup_stack_light.png`
(and `png/inknaut_symbol_light.png` for the symbol alone).

**Dark**: Inknaut Navy background where a filled background is needed (never pure
black); mark and `INKNAUT` wordmark in Inknaut White; terminal rings and `LABS` stay
Inknaut Blue — the one constant across both treatments. Files:
`png/inknaut_lockup_stack_dark.png`, `png/inknaut_symbol_dark.png`. The dark files
have a **transparent** background (not a baked-in navy rectangle) so they composite
cleanly onto any dark surface color, not just the exact splash navy — bake in a solid
background only for a file that explicitly represents a complete splash canvas (see
`splash/`).

Both treatments were generated by classifying the master's own pixels by hue/lightness
(navy vs. blue vs. background) and re-emitting flat, un-fringed colors at the
master's original alpha/coverage per pixel — not by inverting or filtering the light
file. This also fixed a light-halo edge artifact present in an intermediate pass
(recoloring against the assumption that the master's antialiasing blended toward a
pure-white background, then discovering the true edge color needed to be resolved from
alpha coverage directly rather than kept as-is).

## 5. Splash behavior (as implemented and verified in NextUp)

Sequence: **OS launch → Inknaut Labs publisher mark → app content**, targeting well
under 1.2s total for the publisher-mark phase.

1. **Platform-level phase** (Android `SplashScreen` API via
   `androidx.core:core-splashscreen`, themed through `values/themes.xml` and
   `values-night/themes.xml`): paints **only the correctly-colored background**
   (white for light, Inknaut Navy for dark) with **no icon**. This is a deliberate,
   verified choice — showing a platform-drawn icon at this layer *and* the Compose
   lockup immediately after produced two visually distinct marks in quick succession
   (a small icon-only flash, then the full lockup), which read as a stutter/double
   splash rather than one clean reveal. Keeping this phase icon-less removes that
   without needing a fake pre-content Activity.
2. **App-level phase**: a single Compose screen (`InknautSplashScreen`) shown for a
   fixed ~600ms, rendering the full stacked lockup (`inknaut_lockup_stack_light.png` /
   `_dark.png`) centered on a `Box` filled with the matching background color, then
   handing off to the app's real first screen.
3. **Theme resolution split**: the platform-level phase can only follow the *system*
   light/dark setting (it draws before any app code runs, via the `values`/
   `values-night` resource-qualifier split). The app-level Compose phase re-resolves
   against the user's actual saved appearance setting (Light/Dark/System), so it
   always shows the correct treatment even on the rare device where a user has pinned
   an in-app appearance opposite their system setting — that correction happens
   within the same sub-second budget, so it's never a visible problem in practice.
4. No animation beyond the fixed-duration hold and hand-off. The full-bleed
   `splash/inknaut_splash_{light,dark}.png` canvases (1080×2400, phone aspect ratio)
   are reference examples of the resulting visual output for documentation/other
   platforms — NextUp's actual Android implementation composites the transparent
   lockup PNG over a solid-color Compose `Box` at runtime rather than loading these
   full-canvas files directly, since that scales cleanly to any screen size without
   needing per-density pre-baked canvases. A future app on a platform without an
   equivalent runtime-compositing layer may load these canvases directly instead.

## 6. About-screen treatment (as implemented in NextUp)

Settings → About shows, centered as one block: the app's own name, its version
(`Version X.X.X`, from the platform's own build-version field), the line "An Inknaut
Labs app", and the compact stacked lockup (`inknaut_lockup_stack_{light,dark}.png`,
sized to roughly 120dp/120px wide) below it — matching the app's own resolved
light/dark state, not a raw system check. The individual app's own name stays the
first and most prominent line; the publisher lockup is a small, restrained footer, not
a rebrand of the settings screen.

## 7. Publisher vs. product boundary

Inknaut Navy/Blue are for startup, About, and reusable brand assets only — never an
app's product palette, category colors, or general UI theming. Each Inknaut Labs app
keeps its own icon, product palette, typography, and UI personality; what stays
constant is the Inknaut mark, wordmark, publisher colors, light/dark treatments,
startup sequence, and About attribution.

## 8. Asset inventory

All files below share identical mark geometry — only crop bounds, color, and canvas
differ. None were hand-traced or re-vectorized from each other; each was derived
independently from `source/inknaut_master.png`.

| File | Size | Contents |
|---|---|---|
| `source/inknaut_master.png` | 1536×1362, RGB | Canonical reference. Never edited or shipped directly into an app. |
| `png/inknaut_symbol_light.png` | 1012×790, RGBA (transparent bg) | Symbol only, Inknaut Navy mark, Inknaut Blue terminals |
| `png/inknaut_symbol_dark.png` | 1012×790, RGBA (transparent bg) | Symbol only, white mark, Inknaut Blue terminals |
| `png/inknaut_lockup_stack_light.png` | 1407×1204, RGBA (transparent bg) | Symbol + stacked `INKNAUT`/`LABS`, navy/blue — used in NextUp's splash and About section |
| `png/inknaut_lockup_stack_dark.png` | 1407×1204, RGBA (transparent bg) | Symbol + stacked `INKNAUT`/`LABS`, white/blue — used in NextUp's splash and About section |
| `splash/inknaut_splash_light.png` | 1080×2400, RGB (opaque) | Reference full-bleed splash canvas: white background, light lockup centered |
| `splash/inknaut_splash_dark.png` | 1080×2400, RGB (opaque) | Reference full-bleed splash canvas: Inknaut Navy background, dark lockup centered |

No SVG or vector file exists in this kit. Only raster PNGs, all traceable to the
master through crop/alpha/recolor. If a future app's platform strongly benefits from
vector assets, a vector re-authoring would need to be traced with a real vector tool
directly against `source/inknaut_master.png` and visually diffed against it before
being treated as canonical — do not approximate the curves from description or by eye.

## 9. Reuse instructions

Copy this entire `branding/inknaut/` directory into the new application's repository
unchanged. Give the coding agent a prompt describing the app's own existing theme
architecture and asking it to integrate against this spec — it should implement
splash + About + light/dark integration using the files here without regenerating any
artwork, and should verify the result on-device (both light and dark, restart
persistence, no splash flash/double-logo, no background-color artifact behind the
About lockup) before calling the work done.
